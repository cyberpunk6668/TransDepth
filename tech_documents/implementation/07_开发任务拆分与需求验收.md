# 07｜开发任务拆分、配置交接与验收

状态：实现任务说明书。每个任务应提交源代码、必要的小测试和真实运行证据；本轮交付为设计文档，没有将后续验收框默认勾选。

## 1. 实施顺序与提交粒度

建议一次提交处理一个可验证模块；按依赖推进，不同时启动三个decoder和全部论文实验。每步耗时由数据质量和服务器实测决定，不提前承诺训练用时。

### P0：工程骨架与配置

**文件**：01章目录、pyproject、requirements、Git忽略规则、`config.py`、`contracts.py`。

**步骤**：

1. 初始化本地Git；放入src包与空CLI入口，未实现入口明确报`NotImplementedError`，不能伪造通过。
2. 实现YAML配置的固定合并顺序、路径白名单、未知键拒绝和类型验证。
3. 为run建立唯一ID与只增写日志目录；存在目录时要求明确resume，禁止自动覆盖。
4. 记录Git SHA、dirty diff hash、依赖版本、子模块SHA；正式配对要求可追溯快照。
5. 服务器建环境，执行pip check与CUDA基本检查，产生环境锁文件。

**验收**：包可安装、CLI `--help`可用；拼错`lambda_rel`会报错；缺路径/缺hash不能启动正式作业；干净环境可重建CPU测试环境。

### P1：原始数据盘点与adapter（M1）

**文件**：`data/adapters/`、`depth_io.py`、`manifest.py`、`cli/inspect_data.py`。

**步骤**：

1. 只读列出真实原包结构、文件后缀、图数、完整配对率和缺失项。
2. 确认RFTrans顶层62CAD与额外ClearGrasp重渲染包，后者默认排除。
3. 三来源各自解析RGB、理想/rectified/opaque深度与mask，统一米制z-depth但保留原始编码证据。
4. 16bitPNG不能先转8bit；EXR选择实际深度通道，不能固定假设所有包同一通道。
5. 对至少每源30组允许的Train/Dev样本生成数值与可视化检查；不拿Test异常调规则。

**输出**：inventory、配对错误列表、源适配配置、30组叠图/分位数、编码/单位/坐标验收记录。

**门槛**：RFTrans理想深度来源、比例和首命中语义已核实；未知不能凭肉眼猜范围。先处理坏对齐和深度饱和值，再训练。

### P2：分组、manifest与同步预处理（M1/M2）

**文件**：`split.py`、`audit.py`、`geometry.py`、`transforms.py`、`patches.py`。

**步骤**：

1. 建JSONL规范manifest，缺身份填unknown，样本ID跨来源唯一。
2. 绑定场景/近邻视角/相机/透明喷涂配对；用连通的泄漏组整体切分。
3. 冻结R/S约90/10、Q-known约60/20/20、Select/Confirm约50/50，按组而非凑图数；novel封存。
4. 跨来源hash、近重复、CAD/对象身份审计，报告原novel是否相对联合训练未见。
5. 实现长宽比resize和padding，RGB/深度/mask/valid同步变换，K仅用于几何审计。
6. 生成T/B/U可靠patch覆盖图、每源分布与无关系率。

**验收**：不存在已知组跨role；人工孔洞不被填玻璃；padding不进loss；depth-only有效与mask-known分开存；批处理与单图变换一致。

### P3：官方DINO集成与A小样本基线（M3/M4）

**文件**：03、04对应backbone、reassembly、DPT和heads。

**步骤**：

1. 使用03官方来源下载正确H/16+，记录下载状态与完整hash，严格加载。
2. 验证32blocks/1280/20heads/5prefix、层号、post-RoPE与官方输出。
3. 实现四尺度、公共tail和正值映射。
4. 每源固定8–16图，关闭随机增强，300–1000更新拟合；比较初始化与训练集常数预测。
5. 加入单卡profile：预热20update，测100完整update。

**验收**：正确身份/形状/尺度、误差能下降、允许参数有梯度、无NaN/OOM。训练误差下降50%只是排错参考，不是泛化承诺。

### P4：FAR教师数学与真实attention身份（M5）

**文件**：`far/teacher.py`、`far/relation_loss.py`、attention adapter。

**步骤**：

1. 人工小logits矩阵实现教师、质量保持和KL。
2. 检查beta0、恒定代价、空K、极小m、背景行、零概率。
3. 接入官方post-RoPE完整序列，仅记录所选head。
4. 比较官方SDPA与显式A0@V0；检验P=A0的最终深度身份。
5. 把每源teacher质量、KL幅度、fallback和coverage作为日志，不把热图当有效证据。

**验收**：有限精度下满足不变量；容差基于FP32身份测试预先固定；失败先查RoPE前缀、bias_mask和reshape。

### P5：精确采样与公共预热T0（M12）

**文件**：`data/sampling.py`、`engine/trainer.py`、optimizer与checkpoint。

**步骤**：

1. 每update先生成16条全局样本表，主协议固定7R7S2Q。
2. rank按全局表取microbatch，8卡累积2；loss按单图等权，禁止二次乘域权重。
3. 将样本顺序、增强、LoRA初始化、query抽样分开随机流。
4. T0只训练A读出；首轮约2000update，每250–500看Dev，固定公共checkpoint。
5. 完整记录曝光次数、真实过拟合、最好与最后结果。

**验收**：2卡/4卡/8卡适用分配能保持同16条逻辑样本表；全局16样本梯度与参考归一一致；断点恢复顺序不重不漏。

### P6：oracle候选选择与独立确认（M6）

**文件**：oracle候选、runner、statistics和CLI。

**步骤**：

1. 锁候选head抽样seed；H blocks15/23/31各8head，正beta两档，共48候选。
2. Select约100–200图粗筛，前3在完整Select比较，锁定一个。
3. 在Confirm开封前固定背景/边界容忍量、有效组数量要求及统计方法。
4. Confirm只测试锁定候选，2000次组配对bootstrap。
5. 生成`oracle_lock.json`：T0 hash、数据role hash、候选、最终位置/beta、判定和限制。

**验收**：收益平均为正、单侧95%下界>0且背景/边界约束满足；独立组不足记证据不足。不得Confirm失败后改选第二个再说一次确认。

### P7：单头LoRA与H0/H1/H2配对（M7/M8/M12）

**步骤**：

1. 精确插入Q/K输出行，rank4、eta1、down随机/up零，核对10752参数。
2. 零LoRA身份、仅深度到LoRA的梯度、原骨干hash不变。
3. T0分叉时读出权重相同，三组优化器重置、scheduler重启；H1/H2的LoRA逐元素同初值。
4. 先固定32–64混合训练图拟合，再2000update级别Dev短跑。
5. λ候选筛完共同锁正式T1；完成17/29/43配对种子，每seed自己T0。

**验收**：H1/H2只有关系项设计差别；验证深度、背景、边界和每源loss同时可解释。KL下降而深度无改善只说明关系可拟合。

### P8：数据对照与三架构（M9/M10/M11及§4）

**步骤**：CG-real 0/14/2、Mix-syn8/8/0各自T0/T1；固定主协议选中的位置作最小迁移。再B/16对照和H-B/H-C，各自T0，1/2成对。C有优势才做noSeg、A+Seg/B+Seg、noSemFuse、noDPT和容量约±10%对照。

**验收**：原12主配置+4数据控制=16配置，三seed=48学生训练结果，额外预热/search不在其中。不得用6次训练估算完整论文。数据差分是固定预算下替换曝光效果，不能说额外数据的纯增量。

### P9：导出与封存终评（M13/M14）

**步骤**：独立FP32副本merge、同Dev RGB误差对照、禁止标签文件访问的预测测试；锁实验列表和指标后生成Test RGB清单；先保存预测，再独立读GT/mask评价。

**验收**：只靠RGB可运行；预测单位米，无GT尺度对齐；透明/背景/边界逐域逐图再按组宏平均；seed波动与测试组置信区间分别报告。测试失败样本保留失败统计，不删NaN像素获利。

## 3. 配置模板必须能阻止错误实验

实施时在schema里强制以下条件：

```text
canvas == (384,512)
primary_backbone == dinov3_vith16plus
effective_batch == world_size * microbatch * accumulation == 16
sum(source_counts) == 16
train_roles disjoint from dev/select/confirm/test
far_enabled implies oracle_lock exists and passed
selected_head in model head range; selected_block in block range
lambda_rel == 0 for H1; lora rank/eta/location identical in H1/H2
optimizer parameters subset of allowed trainable names
runtime infer implies no label manifest fields and no teacher
```

正式H2需要通过的oracle锁；机制诊断如beta0、随机头使用明确`experiment_kind=mechanism_control`，不能绕过门槛后冒充主结果。开发用人工模型测试和正式运行模式分开标识。

## 4. 每次运行的最小产物

```text
run_dir/
  run_manifest.json          # ID、来源协议、seed、代码/权重/数据hash
  resolved_config.yaml
  environment.json
  sample_schedule.jsonl      # 或等价可恢复索引表及hash
  trainable_parameters.json
  logs/metrics.jsonl
  checkpoints/{best,last}.pt
  reports/{data,profile,pairing,dev}.json
  predictions/               # 终评时独立生成；含逐图单位与身份
```

这是语义最小集合。05/06可拆更多状态文件；不要同时维护不同内容却同名的两个checkpoint。checkpoint原子写临时文件后rename，只有完整update才移动“last”指针。

## 6. 不应被误报为完成的事项

- 源码仓库可以建立与可训练项目已通过集成验收是两件事。
- 官方模型名查对与权重已成功下载是两件事。
- 有可行数据解析公式与实际发布包已通过单位/首表面验收是两件事。
- PyTorch依赖已列出与3090上forward/backward稳定是两件事。
- 单元检查通过与FAR真实域有效是两件事。
- oracle阳性与小秩RGB学生学会是两件事。

本轮的完成范围是整套设计文档。开始代码实施后，逐项填入实际产物、命令退出码、Git SHA、数据/模型hash和评价结果；没有证据的项目保持未完成。
